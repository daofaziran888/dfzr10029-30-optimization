# 数据分析实验与数据应用服务平台

面向指标口径管理、分析实验设计、OLAP查询、数据看板构建与数据API发布的数据应用平台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm ci
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 数据集市授权口径

数据集市页读取集市数据时，先把集市表主题域、用户组与关联维度版本数据清洗一遍，
再按主题域和用户组过滤集市数据：

- 用户组来自「分析用户组」的 `数据可见性`（主题域）与 `授权维度`（关联维度），
  并与 `mart_authorization` 中有效版本记录叠加；维度版本里已停用的维度不参与授权。
- `主题域` 口径：只返回授权主题域的集市表，未授权主题域整表不可读。
- `关联维度` 口径：授权主题域内的表可读；跨主题的表只有在命中已授权关联维度时
  才可打开，且该主题域的度量会被屏蔽（`被屏蔽度量`），避免跨主题读取未授权度量。
- 两种口径都会裁剪 `关联维度`，并在响应里给出 `可读维度`、`被过滤维度` 与
  `授权依据`；导出文件同样列出被过滤维度与授权依据。
- 不带 `group` 参数时保持平台管理视图（全量维护），前端顶部可切换用户组与角色。

集市授权过滤记录（`/api/mart_authorization`）是版本输入：

- 同一 `来源段`（默认 `用户组:主题域`）只保留一个有效版本，历史版本保留以便追溯。
- 处理次序落后于既有记录、或主版本号超出主版本边界的记录进入「冲突」，等待核对。
- `POST /api/mart_authorization/reconcile` 消费记录并核对主版本边界，结果持久化回记录；
  历史版本（已回退/已替换/已归档）不参与主版本核对。
- `GET /api/mart_authorization/{id}/trace` 回溯同一来源段的版本链、变更轨迹与结果数据流。
- 写操作需要 `X-Operator` / `X-Role` 头（或同名载荷字段）：只读角色只能查看，
  非管理员不能改动他人归属的数据。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
